# nongyak-kb

농촌진흥청 **PSIS(농약안전정보시스템) OpenAPI**를 전량 수집해 오프라인에서 검색·질의할 수 있는 농약 사용기준 지식베이스입니다.

인터넷 없이 동작하는 SQLite 단일 파일, RDF/TTL 온톨로지, 그래프 JSON, CLI, 정적 웹앱으로 구성됩니다.

| 항목 | 건수 |
|---|---|
| 사용기준 (작물 × 병해충 × 약제) | 144,073 |
| 제품(품목) | 3,961 |
| 병해충·잡초 | 990 |
| 작물 | 428 |
| 등록취소 이력 | 400 |
| 분석법 | 385 |

---

## ⚠️ 사용 전 반드시 읽어주세요

**이 저장소는 참고용이며, 실제 방제 판단의 근거로 단독 사용해서는 안 됩니다.**

- 농약은 **제품 라벨과 최신 공식 정보가 최종 기준**입니다. 등록 내용은 수시로 변경됩니다.
- 데이터는 수집 시점(2026-07-24)의 스냅샷입니다. 이후 변경은 반영되어 있지 않습니다.
- **등록취소 여부는 추정입니다.** PSIS 등록취소 목록은 품목등록번호로 식별되는데 제품 목록에는 품목코드만 있어, 품목명·상표명·회사명 3중 일치로 대조합니다. 회사명 표기가 바뀐 사례 등 일부는 판정되지 않습니다([알려진 한계](#알려진-한계) 참고).
- 안전사용기준(수확 전 일수, 사용 횟수)과 희석배수는 원문을 그대로 보존하지만, 적용 여부는 사용자가 라벨로 확인해야 합니다.

## 빠른 시작

```bash
bun install
```

### 이미 만들어진 DB가 있는 경우

```bash
bun run cli -- query "고추 탄저병"
```

### 처음부터 수집하는 경우

PSIS OpenAPI 인증키가 필요합니다. [공공데이터포털](https://www.data.go.kr)에서 발급받아 `.env`에 넣으세요.

```bash
cp .env.example .env      # PSIS_API_KEY=발급받은-인증키
bun run fetch             # 전량 수집 (약 1시간, 중단 후 재개 가능)
bun run normalize         # data/kb.sqlite 생성
bun run export            # dist/ontology.ttl, dist/graph.json 생성
bun run compress          # data/kb.sqlite.gz 생성 (웹앱용)
```

키 없이 구조만 확인하려면 `bun run fetch --mock`으로 `fixtures/`의 샘플을 사용할 수 있습니다.

## CLI

```bash
bun run cli -- <명령>
```

### `query` — 통합 검색

작물·병해충·품목명·상표명·회사·영문명·성분명 7개 컬럼을 부분일치로 검색합니다. 공백으로 구분한 여러 단어는 AND로 결합되므로 `"고추 탄저병"`처럼 작물과 병해충을 함께 넣을 수 있습니다.

```bash
bun run cli -- query "고추 탄저병"
bun run cli -- query "strobin" --limit 100     # 계열 접미사 검색
bun run cli -- query "가네마이트" --json        # RAG 소비용 JSON
```

출력(TSV): `품목명 상표명 회사 작물 병해충 희석배수 사용적기 안전사용기준 등록상태`
`--json`은 `v_usage` 행 배열에 `revoked` 불리언이 붙습니다. 결과가 `--limit`에서 잘리면 stderr로 알립니다.

### `product` — 제품 상세

```bash
bun run cli -- product "가스가민"
```

품목코드·주성분·작용기작·독성·어독성·등록상태와 해당 제품의 사용기준 전체를 출력합니다. 등록취소된 옛 제형도 별도 항목으로 함께 보여줍니다.

### `rotate` — 작용기작 로테이션 추천

같은 계열 약제를 반복 사용하면 저항성이 생깁니다. 올해 쓴 약제를 넣으면 **계열이 겹치지 않는** 약제를 권장합니다.

```bash
bun run cli -- rotate "고추 탄저병" --used 만코제브
bun run cli -- rotate "사과 점무늬낙엽병" --used 카브리오팀 --used 다3
```

- `--used`는 약제명(상표·품목 부분일치) 또는 작용기작 코드를 받습니다.
- 등록취소 제품은 처방에서 제외하고 건수를 보고합니다.
- 입력이 여러 제형에 걸쳐 계열 해석이 갈리면 경고합니다. 정확한 상표명을 주면 해석이 확정됩니다.

### `stats`

```bash
bun run cli -- stats     # 테이블별 건수와 DB 생성 시각
```

## 웹앱

`web/`은 서버가 필요 없는 정적 페이지입니다. sql.js(SQLite WASM)로 브라우저에서 직접 DB를 읽습니다.

```bash
python3 -m http.server 8000
# http://localhost:8000/web/
```

첫 로드에서 91.5MB 원본 대신 13.3MB gzip 압축본(`data/kb.sqlite.gz`)을 받아 브라우저에서 해제합니다. 압축본이 없으면 원본으로 자동 폴백합니다.

CLI와 **같은 컬럼·같은 매치 규칙**을 쓰므로 양쪽 검색 결과가 일치합니다.

## 산출물

| 경로 | 내용 |
|---|---|
| `data/kb.sqlite` | 정규화 테이블 + `v_usage` 뷰 + FTS5 색인 (91.5MB) |
| `data/kb.sqlite.gz` | 위 파일의 gzip (13.3MB, 웹앱 초기 로드용) |
| `dist/ontology.ttl` | RDF 온톨로지 (약 120만 트리플) |
| `dist/shapes.ttl` | SHACL 제약 |
| `dist/graph.json` | 노드/엣지 그래프 (제품·성분·작물·병해충·회사) |

소비자(CLI·웹앱·exporter)는 원시 테이블이 아니라 정규화 테이블과 `v_usage` 뷰만 사용합니다. 계약은 `contracts/`에 있습니다.

```bash
# SHACL 검증 (pyshacl 필요)
python -m venv .venv-shacl && .venv-shacl/bin/pip install pyshacl
.venv-shacl/bin/python scripts/validate-shacl.py dist/ontology.ttl dist/shapes.ttl
```

## 데이터 수집 시 주의점

PSIS API를 직접 다룰 때 걸리기 쉬운 함정들입니다. 전부 `contracts/api-spec.md`에 기록돼 있습니다.

- **`startPoint`는 페이지 번호가 아니라 1-기반 아이템 오프셋입니다.** 매뉴얼 설명과 다릅니다. 페이지로 착각하면 데이터의 대부분을 놓칩니다.
- **`journal_mode=WAL`을 쓰면 안 됩니다.** 웹앱의 sql.js가 메인 DB 파일만 읽으므로 모든 데이터가 단일 파일에 있어야 합니다.
- 외장 볼륨에서 대량 쓰기 시 `EINTR`이 발생할 수 있어 `fetch.ts`에 재시도가 들어 있습니다.
- `applyFirstRegDate`는 사용기준별로 다르게 옵니다. 제품 속성으로 쓸 때는 최소값을 취해야 수집 순서에 흔들리지 않습니다.

## 알려진 한계

- **등록취소 미탐 가능** — 회사명 표기가 달라진 경우(`(주)탑프레쉬` ↔ `(주)탑후레쉬`) 대조되지 않습니다. 편집거리 매칭은 정상 등록 제품을 취소로 오인할 위험이 커서 넣지 않았습니다.
- **등록취소 과잉 전파 가능** — 품목명·상표명·회사가 같은 제품이 복수 품목코드로 등록된 경우, 취소 1건이 여러 제품에 표시될 수 있습니다. 현재 필드로는 어느 쪽이 취소인지 구분할 수 없습니다.
- **복합제 성분명 파싱 불완전** — `"... WP 22(2+20) %"`처럼 함량이 괄호로 표기된 복합제는 성분명 추출에 실패해 제품 스펙 문자열이 그대로 성분으로 남습니다(3,961개 중 약 39%). 그래프의 성분 축이 복합제에서는 제대로 묶이지 않습니다.
- **웹앱 자동 테스트 없음** — 검색·필터·압축 로드는 실브라우저 수동 검증에 의존합니다.
- **품목등록번호 중복** — PSIS가 같은 등록번호를 서로 다른 제품에 재사용하는 사례가 있어 등록취소 1건이 저장되지 않습니다. `normalize` 실행 시 건수를 보고합니다.
